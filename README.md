# 링크 스크랩 (옵시디언 플러그인)

링크를 넣으면 글 본문을 가져와 `스크랩` 폴더에 노트로 저장한다. 원문/한국어 번역, 전문/요약 중에서 골라 저장할 수 있고, 번역·요약은 마지막에 PC의 Claude가 확인한다. PC·모바일 공용.

## 설치 (휴대폰·다른 기기)

1. 옵시디언 설정 → 커뮤니티 플러그인 → 탐색 → **BRAT** 설치 후 켜기
2. 명령 팔레트 → `BRAT: Add a beta plugin for testing` → `smkim1502-creator/obsidian-link-scrap` 입력 → 추가
3. 커뮤니티 플러그인 목록에서 「링크 스크랩」 켜기

새 버전은 BRAT이 자동으로 받아 온다. 배포: `manifest.json`의 version을 올리고 같은 이름의 태그를 push하면 GitHub Actions가 릴리스를 만든다.

PC(이 노트북)는 BRAT 없이 `node build.mjs --install`로 Vault 플러그인 폴더에 복사한다. 1.6.1부터 옵시디언이 켜져 있어도 6초쯤 안에 플러그인이 스스로 새 파일을 다시 불러오고 `링크 스크랩 1.6.0 → 1.6.1 업데이트` 알림을 띄운다 (`src/selfupdate.js`). Claude가 노트를 마무리하는 중이면 끝난 뒤에 한다. 지금 불린 버전은 플러그인 폴더 `data.json`의 `loadedVersion`에 적힌다.

## 저장 형식

```markdown
---
url: https://brunch.co.kr/@hiclemi/152
tags:
  - AI
---
# 글 제목

본문…
```

- 파일 이름 = 글 제목. 같은 이름이 있으면 `제목 (2).md`
- **폴더 자동 분류** (1.2.0~): 비슷한 스크랩·같은 사이트 글이 모인 하위 폴더(예: `스크랩/AI`, `스크랩/게임/공식`)를 고른다. 어느 폴더와도 안 맞으면 `스크랩`에 둔다. 기존 스크랩 기준 적중률 80%, 닌텐도 키워드 시리즈 99%
- **자동 태그·관련 노트** (1.1.0~, 외부 API 없이 기기 안에서 계산)
  - 태그: 저장할 폴더에서 주로 쓰는 태그(예: `스크랩/AI` → `AI`) + 본문에 이름이 여러 번 나오는 기존 태그 + 아주 비슷한 노트의 태그. 입력창에 쓴 태그와 합쳐진다
  - 관련 노트 (1.3.1부터 기본 끔: 노트 링크는 옵시디언을 정리할 때 한꺼번에 한다): 켜면 내용이 비슷하거나 본문에 제목이 나오는 **내 노트**(스크랩 폴더 밖)를 frontmatter 아래 `관련 노트: [[…]]` 줄로 최대 3개
  - 기존에 직접 달아 둔 링크로 측정한 적중률: 스크랩 62%, 닌텐도 키워드 시리즈 86% / 태그 71% (`node test/eval_related.mjs`)
- 이미 스크랩한 링크(추적용 파라미터만 다른 경우 포함)는 새로 만들지 않고 기존 노트를 연다
- PDF 링크는 PDF 파일을 같은 폴더에 저장하고 노트에 임베드한다
- 본문을 못 찾는 페이지(SNS 등)는 미리보기 요약 글만 저장하고 알림으로 알려준다

## 쓰는 법

| 방법 | 동작 |
|------|------|
| 왼쪽 리본의 신문 아이콘 / 명령 `링크 스크랩` | 입력창. 클립보드에 링크가 있으면 자동으로 채워짐. 폴더(기본: 자동 분류)·태그를 정하고 저장 형태 버튼(원문·전문 / 원문·요약 / 번역·전문 / 번역·요약)을 누르면 저장 |
| 명령 `클립보드 링크 빠른 스크랩` | 클립보드 링크로 "어디로 보낼까요" 창을 띄운다. 위쪽은 **켜 둔 이유** 버튼(탭 보내기), 아래쪽은 저장 형태 버튼 네 개(본문 스크랩, 자동 분류, 끄면 마지막에 고른 폴더) |
| `obsidian://scrap?url=…` | 다른 앱에서 호출 (모바일 공유 시트용). 같은 "어디로 보낼까요" 창을 띄운다. `&reason=읽을거리&why=주말에`면 묻지 않고 그 이유로 보낸다. `&folder=스크랩/AI` `&tags=AI,경제` `&ask=1`(입력창 띄우기) 선택. 형태를 주소에 적으면(`&translate=1` 한국어 번역, `&summary=1` 요약, 0이면 원문·전문) 묻지 않고 저장 |
| 명령 `Claude 확인 대기 노트 모두 마무리` (PC) | 확인 대기 표시가 있는 노트를 지금 마무리 (보통은 자동으로 함) |
| 명령 `이 노트 Claude로 마무리` (PC) | 열어 둔 확인 대기 노트를 마무리. 초안을 고친 노트도 덮어쓴다 |
| 명령 `Claude 확인 기록 열기` | `스크랩/Claude 확인 기록` 노트를 연다. 아직 확인 대기인 노트 목록과, 노트마다 Claude가 언제 무엇을 고쳤는지(고친 줄의 전후) |

## 여러 편으로 나뉜 글 — 1.14.0

닌텐도 「개발자에게 물어보았습니다」처럼 1편 `index.html`, 2편 `02.html` …로 나뉜 글은 어느 편 링크를 넣어도 전부 받아 **노트 하나**로 저장한다 (`findParts`·`scrapSeries`).

- 같은 폴더 안의 `index`·숫자 이름 페이지를 2~12개 링크한 경우만 나뉜 글로 본다
- 편마다 `## 1. 편 제목` 소제목(목차 버튼의 제목, 없으면 `N편`). `url`은 1편 주소라, 다른 편 링크로 다시 넣어도 이미 스크랩한 글로 알아본다
- 요약도 같은 소제목 아래 항목으로 나눈다. 대담은 말한 사람을 `**이름:**`으로 붙여(닌텐도 인터뷰 규칙) 요약에서 누가 한 말인지 밝힌다
- 못 받은 편은 그 자리에 주소를 남기고 알림에 적는다

## 탭 보내기 (켜 둔 이유) — 1.5.0

휴대폰 브라우저 탭이 쌓이지 않게, 탭을 닫기 전에 "왜 켜 뒀는지"를 골라 옵시디언에 남긴다.

- 이유 버튼을 누르면 `수집함/{이유 이름}.md`에 `- [ ] [제목](주소) — 이유 한 줄 (날짜)`이 쌓인다. 같은 주소는 한 번만
- 기본 이유: 해 보고 싶은 것 · 읽을거리 · 볼거리 · 생각 재료 · 만들고 싶은 것 · 사고 싶은 것. 정해진 목록이 아니다
  - 창의 `+ 새 이유`로 이름을 적으면 이유가 생기고 바로 보낸다
  - 설정 → 탭 보내기에서 이름 바꾸기·순서·지우기·이유마다 저장 방식(링크만 / 본문도 저장(원문) / 본문도 저장(외국어는 한국어 번역))
- 본문도 저장하는 이유(기본: 읽을거리)는 먼저 스크랩하고 `[[스크랩 노트]] · [원문](주소)`로 적는다. 노트는 열지 않는다. 스크랩이 막히면 링크만이라도 남긴다
- 링크만 남기는 이유는 페이지 제목만 가져온다. 구글 검색은 페이지를 받지 않고 `구글 검색: 검색어`로 적는다

## 번역·요약

입력창에서 **언어**(원문 / 한국어 번역)와 **분량**(전문 / 요약)을 고른다. API 키는 쓰지 않는다.
초안은 무료 방식으로 만들고, 마지막에 PC에 설치된 Claude Code(로그인한 구독 계정, `claude -p --safe-mode`)가 확인해 최종본으로 만든다.

| | 초안 (휴대폰·PC) | Claude 마무리 (PC) |
|---|---|---|
| 전문 번역 | 구글 번역 웹 주소(키 없음)로 마크다운째 번역. 이미지·링크 주소·코드·표 구분선은 자리표시로 지켜 둔다. 1~6초 | 원문과 구글 번역을 줄마다 짝지어 보여 주고, 오역·빠진 내용·고유명사·어색한 문장을 고친 줄만 받아 바꾼다. (Haiku 기준) 짧은 글 10~20초, 1만 6천 자 약 1분 40초, 3만 7천 자 약 5분. Sonnet은 생각을 덜 해서 묶음당 절반쯤 |
| 요약 | 기기 안에서 핵심 문장 3~6개를 골라 목록으로 (TextRank: 다른 문장과 많이 겹치는 문장 + 첫머리·제목 가산점). 번역+요약이면 고른 문장만 구글 번역 | 원문을 읽고 새로 쓴다. 1.13.1부터: 누가 무엇을 말했는지 한 문장 + 원문 순서대로 주제(인터뷰는 질문)마다 항목 하나. 주제는 골라 버리지 않되 각 항목은 한두 문장(100자 안팎)으로 짧게, 이름·이유는 살리고 인상적 예시는 따옴표로 인용, 같은 이유로 내린 결정은 한 항목으로, 경력 소개·기자 일화는 뺀다. 필요 없는 항목은 사용자가 지운다. 번역+요약이면 바로 한국어로. 2만 자 인터뷰 기준 30초쯤 |
| 외국어 제목 별칭 | 구글 번역 | Claude가 다시 옮긴다 |

- **PC에서 스크랩**하면 Claude가 마무리한 결과를 바로 저장한다
- **휴대폰에서 스크랩**하면 초안을 저장하고 frontmatter에 `Claude: 번역 확인 대기 (3f2a1b9c)` 같은 표시를 단다. PC 옵시디언이 동기화로 이 노트를 받으면(켜 두었으면 동기화 뒤 15초쯤, 꺼져 있었으면 다음에 켤 때) 원문을 다시 받아 마무리하고 표시를 결과로 바꾼다. 제목이 바뀌면 파일 이름도 바꾼다
- 괄호 안은 초안의 지문이다. 마무리 전에 노트 본문(또는 별칭)을 고쳤으면 고친 내용을 지키려고 마무리하지 않는다. 그래도 마무리하려면 PC에서 노트를 열고 명령 `이 노트 Claude로 마무리`
- 전문 번역을 처음부터 Claude에게 맡기지 않는 이유: 시험해 보니 Claude가 기사·에세이 전문 번역은 저작권을 이유로 대부분 거절하고 요약을 내놓았다. 이미 있는 번역문을 원문과 대조해 고치는 일은 한다
- 긴 글은 원문+번역 8,000자 안팎씩 나눠 두 개씩 동시에 확인한다(Claude Code 하나가 메모리 200MB 남짓). 한자·가나 글이면 먼저 고유명사 표기를 정해 모든 묶음에 같은 이름을 쓰게 한다
- Claude가 실행되지 않으면(로그인 만료·사용량 한도·시간 초과) 초안으로 저장하고 확인 대기 표시를 단다. Claude가 응답했지만 쓸 수 없는 결과(거절 등)면 초안을 그대로 두고 `못 함`으로 표시한다

### Claude가 확인했는지 보기 (1.4.0~)

- 노트 frontmatter의 `Claude` 값이 지금 상태다. 휴대폰에서도 속성으로 보인다
  - `번역 확인 대기 (3f2a1b9c)` — 아직 PC가 마무리하지 않음
  - `번역 확인 완료 · 2026-10-30 14:20 · 42줄 중 12줄 고침` — Claude가 확인함 (요약은 `요약 완료 · 날짜`)
  - `번역 확인 일부만 완료 · …` — 긴 글의 일부 묶음을 Claude가 확인하지 않아 구글 번역 그대로
  - `번역 확인 못 함 · 날짜 · 이유` — Claude가 거절했거나 원문을 다시 받지 못해 초안 그대로
- `스크랩/Claude 확인 기록` 노트(PC가 쓰고 동기화로 휴대폰에서도 봄): 맨 위에 아직 확인 대기인 노트, 그 아래 최근 100개 기록(최신이 위)
  - 번역: 고친 줄을 접힌 상자에 전후로 보여 준다(취소선이 구글 번역, 그 아래가 Claude). Claude가 고쳤지만 내용이 빠지거나 링크가 사라져 받지 않은 줄 수도 적는다
  - 요약: 바꾸기 전 초안(핵심 문장 고르기)을 접힌 상자에 남긴다. 최종 요약은 노트에서 본다
  - 노트를 고친 흔적이 있어 건너뛴 경우, 실행 실패로 미룬 경우도 남긴다
- 1.4.0 전에 마무리한 노트에는 결과 표시가 없다
- 고친 줄은 이미지·링크 자리와 줄 앞 마크다운 기호가 그대로이고, 구글 번역보다 절반 넘게 짧아지지 않았을 때만 쓴다

- 한국어 글은 번역하지 않는다 (한글이 글자의 절반 이상이면 한국어 글. 영어 단어는 한 단어를 한글 1.5자로 친다)
- 요약이든 전문이든 이미지 없이 글만 저장한다(1.3.2~). 이미지·링크 걸린 이미지와 그에 딸린 「이미지 확대」 글자, 뉴스 사진 설명(이메일로 끝나는 설명과 굵은 사진 제목, 이미지 바로 아래 기울임꼴 설명)도 뺀다. 원문은 `url`로 찾아간다
- 번역하면 제목도 한국어로 바뀌고, 폴더 자동 분류·태그·관련 노트도 한국어로 옮긴 글로 계산한다
- 원문으로 저장한 외국어 글은 한국어로 옮긴 제목을 `aliases`에 넣는다 (기존 일본어 스크랩 노트와 같은 방식)
- 구글 번역이 막히면(HTTP 429 = 요청이 너무 많음, 5xx) 2초·6초 쉬었다가 두 번 더 보낸다 (1.6.2~)
- 그래도 안 되면 원문으로 저장하고 알림에 이유를 적되, `Claude: 번역·요약 확인 대기` 표시를 남겨 PC가 마무리한다. 번역만 고른 노트는 PC가 구글 번역 초안부터 다시 만든다 (1.6.2~, 그 전에는 표시 없이 원문으로 끝났다)
- PDF와 본문을 못 찾은 페이지(미리보기만 저장)는 번역·요약하지 않는다 (미리보기는 번역만 함)

### 번역 용어집 (1.8.0~)

`스크랩/번역 용어집.md`(명령 `번역 용어집 열기`, 없으면 만듦)에 `- 원래 표기 → 바꿀 표기`를 한 줄씩 적는다. 휴대폰에서도 고칠 수 있다.

- 왼쪽이 원어(`カービィ → 커비`)면 그 원어가 나오는 글의 번역·요약·별칭에서 Claude에게 그 표기를 쓰라고 알린다. 번역 확인에서는 Claude가 정한 고유명사 표기보다 앞선다
- 왼쪽이 잘못 나온 한국어(`카비 → 커비`)면 한국어로 옮긴 결과(구글 초안·Claude 결과·별칭)에서 바로 바꾼다. 원문 그대로 저장한 노트는 바꾸지 않는다
- 낱말 일부도 바꾸므로 왼쪽은 다른 낱말에 섞이지 않을 표기로 적는다

### 한국 정식 명칭 찾기 (1.9.0~, PC, 1.11.0에서 보강)

외국어 글(일본어·영어 등)을 번역하거나 번역+요약할 때, PC에서 Claude가 마무리하기 전에 고유명사·게임 용어의 한국 정식 표기를 찾는다 (`src/lookup.js`). 글당 1~2분 더 걸린다.

1. Claude가 글에서 고유명사와 게임 속 용어(장소·던전·아이템·적·모드)를 원문 표기 그대로 뽑는다. 일본어 이름은 영어판 이름도 함께 (용어집에 있거나 최근 30일 안에 못 찾은 이름은 뺀다)
2. **위키백과**: 한자·가나 이름은 일본어판, 로마자 이름은 영어판 문서의 한국어판 제목. 원문이 시리즈 이름을 뺀 짧은 이름이면 한국어도 뗀다 (`Wind Waker` → `바람의 지휘봉`, `Ocarina of Time` → `시간의 오카리나`)
3. **웹 검색으로 확인·찾기**: 위키백과 표기가 이 글의 대상과 맞는지 확인한다(게임 속 용어는 위키백과를 쓰지 않음: `パドック` → `예시장` 버림). 없는 이름은 한국 공식 자료(한국닌텐도, 3DS 한국어판 등)에서 근거 주소와 함께 찾는다
4. **공식 누리집 비교**: 검색이 알려 준 같은 게임의 원어판·한국판 공식 누리집을 직접 받아, 원어판에서 그 이름이 나오는 부분과 같은 내용을 한국판에서 찾는다 (`パドック` → `대기소`). 한국판에 실제로 있는 글자만 받는다
5. **참고 자료에서 고르기 (1.12.0~)**: 그 게임의 나무위키 문서(하위 문서 포함, 위키백과에서 찾은 게임 제목으로 주소를 만든다)와 한국판 공식 누리집·인터뷰를 모은다. Claude가 이름마다 한국어 후보를 여러 개 내면, 자료에 2번 이상 실제로 나오는 후보만 원문 문장과 함께 보여 주고 고르게 한다 (`Iron Boots` → `헤비 부츠`: `무거운 철 신발`은 설명 문장 속 낱말이라 버림). 웹 검색 결과도 이 단계의 후보로만 쓴다
6. **팬 위키**: 글의 시리즈에 맞는 팬 위키 하나(Zelda Wiki, WiKirby, Bulbapedia 등)의 다른 언어 이름 표에서 한국어판 이름 (`Bombchu` → `찍폭탄`). 참고 자료가 있으면 거기에도 나오는 표기만 (옛 판·낯선 표기를 거름)
7. **나무위키**: 그래도 못 찾은 이름만 좁혀 나무위키의 그 게임 문서에서 찾는다 (`Talon` → `타론`, `Lon Lon Ranch` → `론론 목장`)
8. 찾은 표기를 용어집의 `## 자동으로 찾은 표기` 칸에 `- 원어 → 표기 %% 출처 %%`로 남기고, 이번 번역부터 쓴다. 틀린 줄은 고치거나 지우면 된다. 위쪽에 직접 적은 줄이 먼저다. `- 3DS → 3DS`처럼 같게 적으면 "그대로 둔다"는 뜻이다

웹 검색·나무위키 결과는 근거 페이지(또는 참고 자료)에 그 표기가 실제로 있어야 받는다. 근거가 없으면 넣지 않는다. 휴대폰은 Claude가 없어 찾지 않고, PC가 마무리할 때 찾는다.

이미 만든 노트는 PC에서 명령 `이 노트 고유명사 정식 표기로 맞추기`: 원문을 다시 받아 위 순서로 찾고, 노트에서 정식 표기와 다르게 쓴 곳만 바꾼다(바로 뒤 조사도 받침에 맞춤: `봄츄를` → `찍폭탄을`). 바꾼 전후는 `Claude 확인 기록`에 남고 승인은 다시 꺼진다.

### 내 최종 승인 (1.7.0~)

Claude를 거친 번역·요약 노트(마무리했든 못 했든)에는 속성 `승인: false`(체크박스)가 붙는다. 읽어 보고 괜찮으면 노트 위쪽 속성의 체크박스를 켜거나 명령 `이 스크랩 승인`을 실행한다. 별칭만 고친 노트는 대상이 아니다.

- 명령 `스크랩 승인 목록 열기` → `스크랩/스크랩 승인.base`(옵시디언 Bases 표, 없으면 만듦): **승인 대기** / **Claude 확인 대기**(PC 마무리 전) / **승인함** 세 보기
- 노트의 `Claude:` 속성에 무엇을 했는지(`번역 확인 완료 · 날짜 · N줄 중 M줄 고침`), `Claude 확인 기록` 노트에 고친 줄 전후가 있다

### 모바일에서 빠르게 쓰기
- **공통**: 설정 → 모바일 → 빠른 실행(Quick action)을 `링크 스크랩: 클립보드 링크 빠른 스크랩`으로 지정
  → 링크 복사 → 옵시디언 열기 → 화면을 아래로 당기기 → 저장 형태 누르기
- **아이폰 공유 시트**: 단축어 앱 → 새 단축어
  1. 단축어 설정(ⓘ)에서 "공유 시트에서 보기" 켜기, 입력 유형 `URL`
  2. 동작 `URL 인코딩` (입력: 단축어 입력)
  3. 동작 `URL 열기`: `obsidian://scrap?url=`[URL 인코딩된 텍스트]
  → 사파리·앱에서 공유 → 단축어 이름 누르기 → 옵시디언에서 저장 형태 누르기

## Remotely Save 자동 동기화 알림 — 1.6.0

Remotely Save는 직접 누른 동기화에만 알림을 띄운다. 자동 동기화(앱을 켤 때·주기·저장 뒤)는 끝나도, 실패해도 조용해서 휴대폰에서는 내 수정이 올라갔는지 알 수 없다. 그 상태로 다른 기기에서 같은 노트를 고치면 한쪽 수정이 사라진다.

이 플러그인이 자동 동기화의 시작·끝·실패를 Remotely Save와 같은 문장으로 띄우고 끝에 `(링크 스크랩)`을 붙인다.

| 때 | 알림 |
|------|------|
| 앱을 켠 뒤 첫 동기화, 주기 동기화 | `1/2 Remotely Save starts running (onedrive) (링크 스크랩)` → `2/2 Remotely Save finished! (링크 스크랩)` |
| 저장 뒤 동기화 | 끝났을 때만 `2/2 Remotely Save finished! (링크 스크랩)` |
| 실패 (인증 만료, 연결 끊김, 변경 비율 보호 등) | Remotely Save의 오류 문장 + `(링크 스크랩)`, 10초 |
| 직접 누른 동기화 | Remotely Save가 스스로 알리므로 띄우지 않는다 |

- 기존 노트를 고칠 때: 앱을 열고 `2/2 … finished!`가 뜬 뒤에 고치고, 다 쓴 뒤 `2/2 … finished!`가 뜨면 나간다
- 기본은 휴대폰·태블릿만. PC는 아래쪽 상태 표시줄에 이미 나온다. 설정 → 동기화 알림에서 모든 기기 / 끔으로 바꾼다
- Remotely Save 0.5.25에서 확인. Remotely Save가 없거나 꺼져 있으면 아무 일도 하지 않는다 (`src/syncnotice.js`)

## 사이트별 처리

| 사이트 | 처리 |
|--------|------|
| 디시인사이드 | PC 주소도 모바일 페이지로 가져옴, 말머리 제거 |

| 네이버 뉴스, 브런치, 루리웹, 티스토리, GeekNews | 본문 영역 직접 지정 |
| 토스증권 콘텐츠 | 화면이 자바스크립트로 그려져서 내부 API로 본문을 받음 |
| 아카라이브 등 Cloudflare 보호 사이트 | 막히면 PC에서는 숨은 브라우저 창으로 다시 시도, 모바일은 실패 알림 |

새 사이트 규칙은 `src/extract.js`의 `SITE_RULES`에 추가한다.

## 설정

- 스크랩 최상위 폴더 (기본 `스크랩`) — 이 폴더와 하위 폴더가 입력창 목록에 나옴
- 폴더 자동 분류 (기본 켬)
- 스크랩 후 노트 열기 (기본 켬)
- 태그 자동으로 달기 (기본 켬) / 관련 노트 자동으로 링크 (기본 끔. 1.3.1로 올리면 전에 켜 둔 것도 한 번 꺼진다), 관련 노트 최대 개수 (기본 3)
- 비교에서 뺄 폴더 (기본 `클로드 코드 프로젝트, 해결해야 할 문제`)
- Remotely Save 자동 동기화 알림 (기본 휴대폰·태블릿만 / 모든 기기 / 끔)
- 번역·요약은 기본값 없음 — 스크랩할 때마다 저장 형태를 고른다
- 외국어 제목에 한국어 별칭 달기 (기본 켬)
- Claude로 마무리 (기본 켬) — PC: Claude Code로 번역 확인·요약·별칭, 휴대폰 초안 마무리. 휴대폰: 초안에 확인 대기 표시 달기
- Claude 모델 (기본 Sonnet / Haiku), Claude Code 실행 파일 (비우면 `~/.local/bin/claude.exe` 등 기본 위치) — PC만

## 개발

```
npm install
node test/run.mjs [url …]   # 실제 사이트로 추출 결과 확인 → test/tmp_out/
node test/transform.mjs [--claude] [--mode=번역,요약,번역요약] [url …]  # 번역·요약 결과 → test/tmp_out/transform/
node test/plugin.mjs        # 가짜 옵시디언 환경에서 플러그인 전체 흐름 검사 (휴대폰처럼 초안 + 가짜 Claude로 마무리 흐름)
node build.mjs && node test/plugin-desktop.mjs  # 빌드한 main.js를 PC처럼 실행 (Claude Code를 실제로 부름: 번역 확인·요약·별칭·휴대폰 초안 마무리)
node test/syncnotice.mjs    # Remotely Save 자동 동기화 알림 (가짜 Remotely Save로 시작·끝·실패 순서 검사)
node test/selfupdate.mjs    # PC에서 새 버전 파일을 스스로 다시 불러오기
node test/google_down.mjs   # 구글 번역이 막혔을 때 다시 보내기·원문 저장+확인 대기
node test/terms.mjs         # 번역 용어집 읽기·지시문·결과 바꾸기
node test/series.mjs         # 여러 편으로 나뉜 글 합치기·닌텐도 인터뷰 말한 사람
node test/lookup.mjs [--real]  # 한국 정식 명칭 찾기 (위키백과 응답 읽기·맥락 확인·용어집 자동 칸)
node test/eval_related.mjs  # 자동 태그·관련 노트 적중률 (실제 Vault 읽기만)
DEBUG=1 node test/real_vault.mjs "스크랩/경제" url …  # 실제 Vault 기준으로 새 글 스크랩 결과·후보 점수 보기 (메모리에서만 저장)
node build.mjs --install    # 빌드 후 Vault 플러그인 폴더에 복사 (켜져 있는 PC 옵시디언이 스스로 다시 불러옴)
```

| 파일 | 역할 |
|------|------|
| `src/extract.js` | HTML → 제목·본문 추출, 사이트별 규칙, 인코딩 처리 |
| `src/scrap.js` | URL 하나를 가져와 마크다운까지 만드는 흐름 (주소 정리·리다이렉트·iframe·차단 감지) |
| `src/related.js` | 자동 태그·관련 노트: 2글자 단위 TF-IDF 유사도, 제목 언급, 폴더 태그 |
| `src/transform.js` | 번역·요약: 한국어 판별, 구글 번역(자리표시로 마크다운 지키기), 핵심 문장 고르기, Claude 번역 확인(줄 짝짓기·묶음 나누기·고유명사 표기)·요약 |
| `src/pending.js` | "Claude 확인 대기" 표시 달기·읽기, 초안 지문(고친 노트 덮어쓰지 않기), 마무리 결과 표시 |
| `src/log.js` | `Claude 확인 기록` 노트: 확인 대기 목록, 노트마다 결과·고친 줄 전후 |
| `src/syncnotice.js` | Remotely Save 자동 동기화의 시작·끝·실패 알림 (플러그인 객체의 상태 갱신 호출을 감싸서 읽음) |
| `src/selfupdate.js` | PC: 플러그인 폴더의 파일이 바뀌면 플러그인을 스스로 껐다 켜기 |
| `src/claude.js` | PC의 Claude Code를 구독 계정으로 실행 (`-p --safe-mode --tools ""`, 정식 명칭 찾기만 `--tools WebSearch`) |
| `src/lookup.js` | 고유명사의 한국 정식 명칭 찾기: 위키백과 한국어판 제목 → Claude 맥락 확인·웹 검색 → 용어집 자동 칸 |
| `src/main.js` | 옵시디언 플러그인: 입력창, 저장(이미지 빼기), 중복 감지, 자동 태그·링크, 설정, `obsidian://scrap` |
| `build.mjs` | esbuild 번들 → `dist/`, `--install` 시 Vault에 복사 |
| `test/` | 추출 검증·플러그인 흐름 검사 |
